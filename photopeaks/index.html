PhotoPeaks

从候选探索到参数化调色

一张照片可以有几种成立的修法。我们希望从照片提出风格意图， 用可解释的颜色与影调控制生成独立候选，再把选择留给用户。

当前样张：在原图上完成调色

四例选自助手读图后首次给参的九组诊断，使用现有 v5b 渲染器、40 个滑块与原图像素，残差 LUT 关闭。 完整配方均能精确回放；学习执行器尚未通过质量验收。以下样张展示参数表达能力。

01CURRENT DESIGN

当前设计：从完整意图到独立候选

规划器观察照片并自主提出风格，执行器理解完整意图，预测滑块与有界残差 LUT。 每个候选从同一原图独立渲染，由用户选择，也可以保留原图。

目前优先打磨执行器。页首样张用助手直接给参检验调色能力；本地预览已支持比较、继续调整与原尺寸导出。

01

可解释控制，完整配方

模型根据图像与完整文字预测白平衡、曝光、曲线、混色和饱和度，小型残差 LUT 补充颜色映射。 参数作用于原图坐标，完整 JSON 可精确回放；外部 LUT 和 XMP 导出为近似。

02

先把风格落实到照片上

受控训练改善了部分目标重建和亮部层次，但学习模型仍有暗脸、黑白残色和风格不鲜明的问题，相关新权重尚未采纳。 当前结合完整成片与主体细节改进监督，让冷暖、影调和色彩差异真正形成值得选择的结果。

03

把最后的选择交给用户

电影、胶片、清透、黑白是可能的方向，最终候选由照片与意图决定。 已准备匿名比较工具，计划邀请 3–5 位独立评委先导评价；当前尚无人类偏好实验结论。

04

JPEG 优先，再扩展能力

先适应相机、手机和已有后期的 JPEG。RAW 与局部控制留作后续扩展； 当前全局颜色映射对相同颜色执行相同处理，独立控制天空与肤色仍有限制。

C1

先预测，再执行

每个候选方向只让视觉模型看一眼原图，给出预测分，不再"跑一遍看看"。本实现规划期生成 0 张、规划耗时 16.5 秒（论文报告其默认配置为约 60 次生成、规划约 250 秒）。

C2

按风格方向搜索，而不是按动作

候选单位从"提亮/加饱和"这类动作，换成"胶片暖调""冷调极简"这类完整方向。K 条链路各做各的（本次运行 K = 2），分数和参数都不互相混合。

C3

允许不改

终选可以判定"原图最好"；另有内容保持门禁，改动破坏画面时整条分支作废。

03METHOD

早期流程：闭环候选搜索
提方向 → 排序 → 独立执行 → 比较终选

从当前照片提出 n 个方向，预测打分后执行 Top-K 条独立分支。 内容检查后比较候选与原图，允许保持不变。记录中的实验采用单轮执行。

05PROCESS

处理一张照片的四步
这是"一轮"的样子，闭环可以走多轮

1

想方向

让模型提出 n 个互不相同的风格方向（n 是可调参数，示例 n = 5；比如胶片暖调、冷调极简、戏剧化）。 像"提亮一点"和"再亮一点"这类同义方向会被要求重写；拍人的照片不许改动脸。

2

先算不做

每个方向只让模型看一眼当前图像，给出预测分：值不值得做、会不会伤画面。 这一步不生成任何图片，也是成本能降下来的原因。

3

各做各的

只做效用最高的 K 个方向（K ≤ n，示例 K = 2），各自在自己的链路里执行、同时进行，互不交流—— 各方向独立执行，比较输出后选择。这样保留多个候选，不对混合结果作数学保证。

4

挑一张，或者不改

把当前状态和 K 个成品放在一起比较，允许直接判"当前状态最好"：第 1 轮就是"原图最好"，直接退出； 否则胜者成为下一轮的起点，最多走 R 轮。另有内容保持检查——改动破坏了画面，整条链路作废。

06EXPERIMENTS

27 张真照片，三种做法对比

照片是我自己拍的 27 张（人像、风光、城市、夜景、食物混着来）。三种做法跑同样的 API： single 只发一句"把这张图修好"；scalar 拆成动作逐个打分选一个（内部单动作基线）； peaks 是本文的完整流程。

策略耗时/张VLM 调用编辑调用内容保持↑BRISQUE↓美学盲评↑
运行配置　n = 5 · K = 2 · R = 1（单轮，即闭环在 R = 1 的特例）；每张平均 7 次 VLM 调用 + 5.8 次编辑调用（概念内的步骤链逐步执行）。 表中数字是这一配置下的实测；架构本身是闭环（R 可调，见 Figure 1）。
评测口径　每个输出只评分一次；评分不参与当次规划，但仍使用同一模型族，不能视为独立的人类审美证据。 按照片配对 bootstrap（2000 次），peaks−single 为 +0.074，95% 区间 [−0.045, +0.193]； peaks−scalar 为 +0.096，区间 [−0.059, +0.259]。两者都跨过零，当前样本尚未建立稳定质量优势。
怎么读这张表　peaks 的盲评样本均分略高，但内容保持和 BRISQUE 更差。 CLIP 相似度会惩罚部分合法外观变化，也可能漏掉内容损伤；BRISQUE 是自然图像质量代理，不能用改动大小解释全部差异。 三种模式的执行预算和门禁也不同，本表是实现内部的探索性比较，尚不能隔离规划方式的因果效果。

终选与门禁的实际行为

判定"不该动手"的情况

所有分支都被门禁否决，或者终选认为原图更好时，系统就交回原图。 PhotoAgent 也有分数未改善时回退的机制；本实现额外加入内容门禁，并在比较时显式保留原图选项。

已知边界　暗光或低质量输入时，判断和编辑都会变难；人像的细节一致性取决于编辑后端的能力； 统一美学评分也无法代替个人偏好。
07ROBUSTNESS

如果不加约束，会出什么问题

早期生成式编辑中观察到四类问题，并尝试相应约束。

不锁内容 → 模型会"加戏"

指令里出现"氛围""层次"，它就可能真的去画前景、加光晕。 做法：每条指令带保持性要求，概念层面禁止"添加类"步骤，门禁用边缘结构相关性复核。

0.40 → 0.99边缘幅值相关性（相似结构的代理，非几何完全一致的证明）

不锁肤色 → 人像被整体染色

"暖光""日落感"这类词很容易把整张图推向橙红，风景还好，脸就明显不对。 做法：概念阶段锁定肤色与身份，融合时只从原片取纹理、不碰颜色。

0.86 → 0.95内容相似度 · 色度噪声 3.2 → 1.17

不做细节融合 → 修完比原图还糊

编辑接口固定返回约 130 万像素，而原片是 2400 万像素，一步接一步重画还会继续掉细节。 做法：影调和颜色取编辑结果，纹理从原片高频补回。

0.21 → 1.00分辨率保留 · 细节能量比 0.97

只看一个总分 → 拦不住局部的坏

全局相似度看的是"还是不是那张图"，局部多画几片叶子、脸偏一点色，它几乎不扣分。 做法：三个本地指标交叉检查（内容相似度、结构相关性、高频色度噪声），越界即整条分支作废。

3 项本地指标交叉检查，任一越界即作废
代价也说清楚　约束变严之后改动更保守，盲评从 4.22 到 4.18，BRISQUE 从 35.6 到 40.4 。这说明约束与质量指标之间存在取舍，尚不能把分数变化归因于单一处理。

实测：通用编辑模型的指令遵循并不可靠

另用猫与城景两张照片检查指令幅度：固定各自输入，改变措辞，观察整体色彩偏移。

指令Δ(R−B) 暖冷偏移Δ 饱和Δ 亮度
"稍微锐化"（不含颜色词）≈ 0≈ 0≈ 0
"提高中间调对比"（纯影调）+3 ~ +12+3 ~ +9−34 / +9
"整体调冷"−57 / −44+29 / +35±10 内
"整体调暖"+50 / +83+46 / +49±10 内
"稍微锐化"连做两步+0.7 / +4.3≈ 0≈ 0

两组数字分别对应两张测试照片（猫、城景）。中性指令下模型几乎是忠实的； 一旦出现"暖/冷/色温"，它就会把整幅图推走 50–80 个单位的暖冷偏移，把饱和度抬高三四十， 在这些样例上，"稍微"没有把修改幅度可靠地限定到预期范围。

这两张照片暴露的是早期生成式模型与提示组合的幅度控制失配，不能据此断言所有通用编辑模型都只能做大动作。 限制动作和检查输出能减少部分问题，但还需要验证执行器能否稳定遵循调色意图。 我们因此转向可记录、可调整的参数化执行，并把质量与控制能力分别检验。

08DISCUSSION

从这些结果，能推到哪里

历史 27 张照片比较发生在本实现内部；模型评分差的置信区间跨过零，尚未建立审美优势。 PhotoAgent 的 MCTS、本文单动作基线和像素平均是不同方法；论文成本只作量级参考。

PhotoAgent 报告的 BRISQUE 不在其四个奖励项内，附录也检验了奖励模型与人类评分的相关性。 后续直接对照需匹配候选数量、执行器与预算，并加入独立偏好评价；当前没有对 PhotoAgent 的性能胜出证据。

参数预测已有 HDRNet、 SepLUT 等工作。 我们关注候选各自的质量、同图的有效选择，以及本地控制与执行成本。

让候选各自成立，再验证用户是否拥有更好的选择。
